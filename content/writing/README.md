# 文字模块：直接编辑 Markdown

每篇文章对应本目录中的一个 `.md` 文件。网站会读取开头的 YAML 属性，再将下面的 Markdown 正文渲染成文章。`README.md` 是说明文件，不会成为文章。

## 最简单的新增流程

在此目录新建 `.md` 文件，只写一级标题和正文：

```markdown
# 新文章标题

第一段正文。

第二段正文。
```

在项目根目录运行 `npm run writing:publish`。脚本会为没有属性区的新文件补上稳定网址、日期、分类、语言和公开状态，重命名为 `日期-标题.md`，检查所有文章，再只提交 `content/writing` 并推送到 Git 的 `main`。部署平台收到 Git 推送后，网站才会更新。已有属性区的文章保持原样；修改其正文后也用同一个命令发布。

不写日期时，脚本使用运行当天的本地日期。旧文章可先命名为 `2024-05-文章.md` 或 `2024-05-17-文章.md`，也可单独运行 `npm run writing:add -- content/writing/文章.md --date=2024-05-17`。归档日期不确定时，使用下方完整属性格式并填写 `date: null`，避免猜测。新文章默认归为 `essay` 且直接公开；需要其他分类或草稿时，脚本整理后修改 `type` 或 `status`，再运行发布命令。

推送需要本机 Git 已登录且位于 `main`，并且没有其他已暂存的修改。只把文件复制到本地目录不会触发线上部署；如果想省去运行发布命令，还需要在这台电脑上持续运行文件监视服务，让它执行同样的提交与推送流程。

## 文件名

- 日期完整：`2026-06-11-蒋村本质.md`
- 只知道月份：`2026-05-人们总是关心相机的型号.md`

当前 73 篇中，63 篇有完整日期，10 篇只确定到月。未知日不补成 01。日期完全未知时使用 `undated-标题.md`，网页归入“日期未注明”。Windows 不允许用于文件名的半角符号会换成对应的全角符号；显示标题仍取自属性中的 `title`。

文件名用于方便查找；网页标题、归档日期和地址以文件内的属性为准。修改标题或日期时，可同时手动重命名文件。重命名文件不会改变文章 URL，只要保留 `slug`。

## 编辑示例

```markdown
---
slug: "jiangcun-coffee"
title: "蒋村本质"
date: "2026-06-11"
order: 17
type: "essay"
status: "published"
lang: "zh-Hans"
---

第一段正文，直接写中文和 "英文引号"。

第二段正文。用空行分段，不需要 JSON 的换行转义。

## 一个小标题

可以使用 **加粗**、*斜体*、[链接](https://example.com)、列表和引用。
```

- `slug`：稳定的网址名称。现有文章通常保留；新增文章必须使用不同的英文小写字母、数字和连字符组合。
- `title`：网页显示的标题。正文不需要再写一遍同名一级标题。
- `date`：原稿归档日期，可以是 `YYYY-MM-DD`、`YYYY-MM`，无法确定时为 `null`。日期不能填不存在的日子。
- `order`：日期相同时的顺序，较小的数字在前；不会覆盖不同日期的先后关系。
- `type`：`essay`（随笔）、`diary`（日记）、`travel`（游记）、`review`（书评或影评）或 `sketch`（写作练习）。
- `status`：`published` 显示在网站上；`draft` 隐藏。不填写此属性时默认隐藏。
- `lang`：中文通常保留 `zh-Hans`；英文正文使用 `en`。

属性区中的英文双引号如属于内容本身，需要按 YAML 规则转义，或将整个值改用单引号包围。正文里的引号和换行可直接输入。属性拼写错误、重复属性、缺少必要属性或重复 slug 会提示文件名并停止内容准备。

## 添加、隐藏和删除

## 正文排版

- 每个自然段之间留一个空行，段首不加空格或 Tab。长段落可在话题、场景转折处分段，不必给每句话单独分段。
- 对话换人时另起一段。可以使用中文引号；使用破折号时写 `—`，不要用 `- `，后者会被当成项目列表。
- 小标题使用 `## 小标题`，前后各留一个空行。不要把整段正文标成标题或整段加粗。
- 场景分隔线统一使用单独一行的 `---`，前后必须各留一个空行。紧接正文下一行的横线会把前面的整段变成大号标题。
- 从 PDF 或其他文件复制时，删去分页符，并接回被分页切断的句子。正常段落仍保留空行。

```markdown
第一段正文。

第二段正文。

---

场景转换后的正文。

## 一个小标题

小标题下的正文。
```

## 本地预览

在项目根目录运行：

```powershell
npm run dev -- --port 3101
```

打开 `http://localhost:3101/writing`。之后每次保存 Markdown 修改，在另一个终端运行：

```powershell
npm run check:writing
```

开发页面会使用重新生成的内容。修改文件名、增加文章或隐藏文章同样执行该命令。遇到 YAML 错误时，先按提示修正源文件再执行；校验通过前不会写入不完整的生成结果。

当前 3100 端口若运行的是生产预览，则需要停止该预览，运行 `npm run build`，再运行 `npm run start -- --port 3100`。生成内容不等于远程部署。

## 插入图片

单独放在一个段落中的图片会使用已经完成的浅灰外框、自然比例和阴影。可选的图片标题显示为图注：

```markdown
![曼谷金色喷泉旁飞起的鸽子](/assets/travel/bangkok/fountain.webp "曼谷 · 喷泉")
```

本地图片保存在 `public/assets/`，正文使用 `/assets/` 开头的网址。原始 HTML 不会执行。文章不会作为 MDX 执行代码。

多张图片连续写在同一段落中（图片行之间不留空行），会组成一叠可以翻页的照片：

```markdown
![三月的路口](/assets/writing/seasons/march.webp "三月")
![四月的路口](/assets/writing/seasons/april.webp "四月")
![七月的路口](/assets/writing/seasons/july.webp "七月")
![十月的路口](/assets/writing/seasons/october.webp "十月")
```

左右按钮、在照片区域聚焦后使用方向键，或横向滑动切换照片；首尾循环，第一张向左到最后一张，最后一张向右回到第一张。下方显示序号和当前照片的图注。堆叠沿用单张图片的外框、展示尺寸和自然比例，点击照片不会放大。切换时只有当前照片做轻微入场，手机和 iPad 使用短暂淡入，后层照片保持静止；前后相邻照片会提前加载并解码。图片行之间留空行时，仍各自显示为独立图片。关闭 JavaScript 时会按顺序展示全部照片。

## 自动生成文件与来源

Markdown 是唯一的文章编辑源。`.generated/writing.json` 是准备与构建期间生成的内部数据，不能手工编辑。原 Obsidian 笔记和 handoff 文件不会自动同步到这里。

旧 JSON 文章已逐篇校验无损转换并备份到 `workspace/writing/replaced-content/markdown-2026-09-22T12-10-07-654Z/`，不参与网站构建或部署。`workspace/writing/markdown-migration.json` 记录文件对应关系和转换时的正文校验值。此后的手动修改无需更新这些历史校验值。

`scripts/import-writing-selection.mjs` 已改为输出 Markdown；它只用于主动重新导入整批 handoff。执行它的 `--write` 会替换当前选稿，可能覆盖手动编辑，不要把它当作日常刷新命令。
