# 旅行内容更新说明

旅行首页路径：`/travel`

旅行详情页路径：`/travel/[slug]`，例如：

- `/travel/hangzhou`
- `/travel/nanjing`
- `/travel/japan`

旅行内容主要由 `content/travel/` 维护。每个城市或目的地一个目录。

## 目录结构

```text
content/travel/
└── hangzhou/
    ├── meta.json
    ├── story.md
    └── cards.json
```

图片文件放在：

```text
public/assets/travel/
```

可以按目的地继续分目录，例如：

```text
public/assets/travel/hangzhou/
public/assets/travel/japan/
public/assets/travel/nanjing/
```

## 新增一个旅行目的地

以新增 `suzhou` 为例：

1. 新建目录：

   ```text
   content/travel/suzhou/
   ```

2. 添加三个文件：

   ```text
   content/travel/suzhou/meta.json
   content/travel/suzhou/story.md
   content/travel/suzhou/cards.json
   ```

3. 把图片放进：

   ```text
   public/assets/travel/suzhou/
   ```

4. `meta.json` 里的 `slug` 必须等于目录名：

   ```json
   "slug": "suzhou"
   ```

只要目录和 `meta.json` 合法，旅行首页会自动读取这个目的地，并生成 `/travel/suzhou`。

## meta.json 字段说明

文件：`content/travel/[slug]/meta.json`

核心字段：

- `slug`：英文路径名，必须和目录名一致
- `zhName`：中文名称，显示在旅行首页
- `enName`：英文名称，显示在详情页 Hero
- `period`：时间，用于旅行首页排序
- `location`：地点说明
- `cardTitle`：卡片和详情页标题
- `cover`：旅行首页卡片封面
- `hero`：详情页顶部大图
- `summary`：摘要，也用于 SEO 描述
- `tags`：详情页 Hero 标签
- `itinerary`：行程数组，目前作为结构化内容保留
- `spots`：景点数组，目前作为结构化内容保留
- `photoStory`：照片故事字段，目前作为结构化内容保留
- `reflection`：回顾字段，目前作为结构化内容保留
- `gallery`：图组字段，目前作为结构化内容保留

旅行首页排序规则在 `src/app/travel/page.tsx`：

- `period` 包含“至今”时排在最前
- 否则读取 `YYYY 年 M 月`，按最近月份排序
- 时间相同时按中文名排序

## cards.json 字段说明

文件：`content/travel/[slug]/cards.json`

结构固定为三组：

```json
{
  "spots": [],
  "bookstores": [],
  "food": []
}
```

页面显示规则：

- `spots`：详情页“景点”模块
- `bookstores`：如果有内容，显示“书店”模块
- `food`：部分目的地显示“美食”模块

每张卡片格式：

```json
{
  "eyebrow": "西溪湿地",
  "title": "在雨中的西溪湿地散步",
  "body": "卡片摘要文字。",
  "imageSrc": "/assets/travel/hangzhou/hangzhou-xixi-rain-walk.jpg",
  "imageAlt": "在雨中的西溪湿地散步",
  "detailBlocks": [
    {
      "text": "展开后的长正文。",
      "imageSrc": "/assets/travel/hangzhou/hangzhou-xixi-rain-walk.jpg",
      "imageAlt": "在雨中的西溪湿地散步"
    }
  ]
}
```

字段说明：

- `eyebrow`：小标题或地点
- `title`：卡片标题
- `body`：卡片摘要
- `imageSrc`：卡片封面图
- `imageAlt`：图片替代文本
- `category`：可选，目前常用于标记“书店”等分类
- `detailBlocks`：展开弹窗里的正文块，至少要有一项
- `detailBlocks[].text`：长正文，JSON 字符串里换行写成 `\n`
- `detailBlocks[].imageSrc`：正文块配图
- `detailBlocks[].imageAlt`：正文块配图说明

## story.md 的作用

文件：`content/travel/[slug]/story.md`

当前读取逻辑在 `src/lib/content/travel.ts`，会把 `story.md` 读入 `bodyHtml`。现在详情页主要展示 `cards.json` 的滑块内容，`story.md` 是长文正文的保留入口。

建议仍然保持每个目的地都有 `story.md`，方便未来恢复长文排版或 SEO 内容。

## 美食模块注意事项

详情页中美食模块目前只对这些 slug 显示：

```text
japan, nanjing, shanghai, beijing, dongbei
```

控制位置：

```text
src/app/travel/[slug]/page.tsx
```

如果新增目的地也需要显示“美食”，需要把新的 slug 加进这个数组，或把显示规则改为“只要 `food` 有内容就显示”。

## 主页旅行卡片

旅行详情和旅行首页由 `content/travel/` 自动读取，但网站主页 `/` 的旅行三张精选卡片仍在：

```text
src/app/page.tsx
```

搜索：

```ts
const travellerShowcaseCards
```

如果想让某个新目的地出现在主页，也要同步更新这里。

## 更新后检查

```bash
npm run check:content
npm run typecheck
npm run dev
```

本地检查：

```text
http://localhost:3000/travel
http://localhost:3000/travel/hangzhou
```

重点检查：

- `slug` 是否和目录名一致
- 图片路径是否存在
- `cards.json` 的三组数组是否都存在
- 每张卡片是否有 `detailBlocks`
- 详情页滑块是否能打开弹窗
- 新目的地是否需要加入主页精选卡片
